# KillMyIdea

> **Try to kill your idea before the market does.**

KillMyIdea is an experimental, open-source AI tool that stress-tests
SaaS and software project ideas against live market evidence and returns
a brutally honest **DON'T KILL IT**, **NOT YET**, or **KILL IT**
verdict.

It combines:

-   **Tavily** for bounded web research
-   **Ollama Cloud** for LLM analysis
-   **Gemma 4 31B Cloud** as the default analysis model
-   **FastAPI + Pydantic** for the backend
-   **React 19 + Tailwind CSS** for the frontend
-   **MongoDB** for the backend's status-check persistence
-   Browser `localStorage` for the client-side verdict history

> **Important:** Scores are decision-support signals, not objective
> probabilities of success. A positive verdict does not guarantee
> success, and a kill verdict does not prove an idea cannot work.

## Why this project exists

Most idea validators try to make an idea sound promising.

KillMyIdea takes the opposite approach:

> **Assume the idea is wrong and look for evidence that proves it.**

The analysis is designed to separate:

-   user-provided information
-   externally gathered evidence
-   reasoned inference
-   unknown / insufficient evidence

When live research is unavailable, the system should say so rather than
pretending that research happened.

## How it works

``` text
User idea
   |
   v
FastAPI /api/analyze
   |
   +----------------------+
   |                      |
   v                      v
Tavily research       User-provided context
   |                      |
   +----------+-----------+
              |
              v
        Evidence Pack
              |
              v
       Gemma 4 31B Cloud
              |
              v
     Structured JSON result
              |
              v
      Pydantic validation
              |
              v
       URL / output sanitizing
              |
              v
        React results UI
```

The research engine performs four bounded search categories:

1.  Competitors
2.  Pricing
3.  Market
4.  Community

It validates URLs, removes duplicate sources, fetches selected source
pages for stronger evidence, assigns confidence, and passes a bounded
evidence pack to the model.

See [`docs/RESEARCH_ENGINE.md`](docs/RESEARCH_ENGINE.md) for the
details.

## Current verdict model

The live backend accepts three verdicts:

-   `DON'T KILL IT` --- available evidence supports continuing
    validation
-   `NOT YET` --- there may be an opportunity, but important assumptions
    remain unresolved
-   `KILL IT` --- available evidence does not justify significant
    investment in the current form

The model evaluates eight factors:

1.  Problem Strength
2.  Market Opportunity
3.  Competition
4.  Differentiation
5.  Monetization
6.  Distribution
7.  Execution Feasibility
8.  Defensibility

The live scores are generated by the LLM and constrained to 0--100 by
Pydantic validation. There is **no hidden weighted mathematical
formula** pretending to calculate an objective probability.

## Quick start

### Prerequisites

-   Node.js
-   Yarn 1.x or a compatible package manager
-   Python 3.10+ recommended
-   MongoDB
-   An Ollama Cloud API key
-   A Tavily API key

### 1. Clone

``` bash
git clone https://github.com/vijaydeepak-vd/killmyidea.git
cd killmyidea
```

### 2. Configure the backend

``` bash
cd backend
cp .env.example .env
```

Fill in:

``` env
MONGO_URL=your_mongodb_connection_string
DB_NAME=killmyidea
CORS_ORIGINS=http://localhost:3000

OLLAMA_API_KEY=your_ollama_cloud_key
OLLAMA_BASE_URL=https://ollama.com/v1/
OLLAMA_MODEL=gemma4:31b-cloud

TAVILY_API_KEY=your_tavily_key
TAVILY_BASE_URL=https://api.tavily.com
```

Never commit `.env`.

### 3. Install Python dependencies

``` bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 4. Start the API

From `backend/`:

``` bash
uvicorn server:app --host 0.0.0.0 --port 8000
```

### 5. Configure the frontend

Create the frontend environment file used by Create React App:

``` bash
cd ../frontend
```

Set:

``` env
REACT_APP_BACKEND_URL=http://localhost:8000
```

### 6. Install and run

``` bash
yarn install
yarn start
```

Open `http://localhost:3000`.

For frontend commands, see [`docs/SETUP.md`](docs/SETUP.md).

## API

The primary endpoint is:

``` http
POST /api/analyze
```

Example:

``` json
{
  "idea": "An AI tool that creates task-specific context packages for coding agents from GitHub issues.",
  "target": "Engineering teams using AI coding agents",
  "monetization": "Subscription",
  "differentiation": "Turns GitHub issues into ready-to-use context packages for coding agents.",
  "problem": "Coding agents fail on large repositories because they lack the right context."
}
```

The response contains:

-   research status
-   research evidence pack
-   source/model information
-   structured AI analysis

See [`docs/API.md`](docs/API.md).

## Research integrity

KillMyIdea deliberately avoids presenting search snippets as
unquestioned truth.

The research pipeline:

1.  Generates four bounded searches.
2.  Filters low-quality/invalid results.
3.  Deduplicates URLs.
4.  Keeps a bounded number of findings.
5.  Fetches selected source pages.
6.  Cleans HTML boilerplate.
7.  Upgrades evidence confidence when source content is successfully
    accessed.
8.  Passes only a bounded evidence pack to Gemma.
9.  Removes model URLs that are not present in the evidence pack.

If research is unavailable, the application labels that state instead of
claiming that live research occurred.

See [`docs/RESEARCH_ENGINE.md`](docs/RESEARCH_ENGINE.md) and
[`docs/AI_ANALYSIS.md`](docs/AI_ANALYSIS.md).

## Demo mode

The frontend contains deterministic demo analyses so the UI can be
demonstrated without spending Tavily/Ollama credits.

Demo results are intentionally deterministic and should not be
interpreted as live market research.

## History

The frontend stores up to eight recent verdicts in browser
`localStorage` under:

``` text
kmi-history
```

No server-side verdict history database is currently used for this
feature.

## Security

-   API keys are loaded server-side.
-   Real `.env` files are ignored by Git.
-   `.env.example` contains placeholders only.
-   Model-generated source URLs are accepted only when they match URLs
    from the evidence pack.
-   User ideas and API credentials are not intentionally written to
    application logs.

Before publishing or deploying a fork, rotate any credentials that have
ever been exposed and verify Git history with a secret scanner.

See [`docs/SECURITY.md`](docs/SECURITY.md).

## Known limitations

-   Each live analysis can issue multiple Tavily searches, so API usage
    can grow quickly.
-   There is currently no rate limiting on `/api/analyze`.
-   Research is bounded rather than exhaustive.
-   Search results can be incomplete or biased.
-   The LLM can still make reasoning errors.
-   Scores are not statistical probabilities.
-   Demo results are deterministic and not live evidence.
-   MongoDB is required by the current FastAPI application even though
    the main analysis flow is not database-backed.
-   The current dependency manifests still contain Emergent-specific
    packages/assets; see
    [`docs/TROUBLESHOOTING.md`](docs/TROUBLESHOOTING.md) before
    attempting a completely independent OSS installation.

## Project status

This repository is an experimental open-source project and a
build-in-public case study.

The goal is to provide a useful reference implementation for
evidence-backed AI analysis, not to claim that an AI verdict can predict
startup success with certainty.
